You can re-write correlated or minus queries with left outer join. Correlated query has to be executed for every row returned by the outer query. Correlated queries are expensive for the optimizer. 

Example:  Get all departments that have no employees. 

Select A.Deptno ,A.Dname , A.Location From Dept A Where Not Exists (Select ‘1’ ;            From Emp B Where B.DeptNo = A.Deptno ) 

Above query can be re-written like below and gives better performance than above. 

Select A.Deptno ,A.Dname , A.Location From Dept A Left Outer Join Emp B On (A.DeptNo =B.Deptno ) Where B.Deptno Is Null 

Unmatched Data Types: The basic remedy for an unmatched data type on a join condition is to materialize correctly matching data types before they participate in a join condition.  

Product Joins: optimizer underestimating the number of rows which will participate. Verify the row counts and compare the estimates with the actual row counts.  Missing join conditions · OR-ed join conditions · Unequal join conditions · Missing, obsolete, or inappropriate statistics. 

solution for an OR-ed join condition is to split the conditions on two or more SELECT statements and combine the results with a UNION operator 

Large redistributions: Separate the skewed portion of the join from the non-skewed portion in separate select statements using a UNION operator to reassemble the consolidated result set. 

Sel e.eno, e.name, e.sal, d.dno from employee e inner join department d on e.do=d.do where e.sal>1000 and e.dno not in (‘2000’,’3000’) Union

Sel e.eno, e.name, e.sal, d.dno from employee e inner join department d on e.do=d.do where e.sal>1000 and e.dno in (‘2000’,’3000’);
